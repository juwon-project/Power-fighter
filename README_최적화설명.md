# 능력자 결투 — 저지연·초경량 v2

## 왜 이전 버전이 더 느리게 느껴졌나

- 이전 개선판이 네트워크 입력 선행 프레임을 **4 → 12**로 높여 조작에 60 FPS 기준 약 **133ms**의 추가 지연을 만들 수 있었습니다. 이번에는 다시 4로 복구했습니다.
- 이전 판의 FPS 표시 기능이 별도의 requestAnimationFrame을 계속 실행했습니다. 이번 버전은 본래 게임 루프를 이용해 진단을 수행합니다.
- 이전 판은 모니터의 전체 해상도로 화면을 출력할 수 있었습니다. 초경량 모드는 최대 960×540으로 출력하고 CSS로 화면을 확대합니다.
- 초경량 모드는 3D/HD 소프트웨어 효과를 끄고 **게임 시뮬레이션은 60회/초 목표**, 화면 그리기는 **최대 30회/초**로 제한합니다. '균형'은 최대 60 FPS 화면과 1280×720 출력, '고화질'은 기존 고화질 옵션입니다.
- 우상단 '진단 표시'를 누르면 **화면 FPS / 게임 FPS / 서버 RTT / 입력 대기**가 나타납니다.

## 배포

1. 이 ZIP을 풀어 `index.html`, `server.py`, `requirements.txt` 등 모든 구성 파일을 `juwon-project/Power-fighter` 저장소 최상위에 올려 이전 같은 이름의 파일을 덮어씁니다.
2. Render의 해당 Web Service를 열고 `Manual Deploy` → `Deploy latest commit`을 누릅니다. 직접 공개 저장소 URL로 만들었을 때 수동 재배포가 필요합니다.
3. 서비스가 Live가 된 뒤 브라우저에서 **Ctrl+Shift+R**로 새로고침합니다.
4. 친구 2명이 접속하여 각각 '진단 표시'를 켜서 증상을 구분합니다.

## 진단 방법

- **화면 FPS가 15~25 근처**: 로컬 렌더링 병목. 초경량 모드와 다른 탭 종료를 시도하고, GPU 가속 설정을 확인합니다.
- **화면 FPS는 30, 게임 FPS는 60 근처**: 초경량 모드가 의도대로 실행 중입니다.
- **화면 FPS가 30인데 게임 FPS가 낮음 + 입력 대기**: 네트워크 lockstep 중단 가능성이 큽니다. 서버 RTT와 다른 플레이어의 연결 상태를 확인해야 합니다.
- **서버 RTT가 100~200ms 이상**: Render 리전과 플레이어 경로 지연이 영향을 줄 수 있습니다. 가까운 리전과 더 안정적인 네트워크가 도움될 수 있습니다.

## 근본적으로 필요한 다음 개발

이 게임은 상대의 미래 입력을 기다리는 **lockstep** 구조라 한 명의 입력이 늦으면 양쪽 시뮬레이션이 멈춥니다. 이를 완전히 해결하려면 **입력 예측 + 롤백 재시뮬레이션** 또는 **권위 서버 + 상태 보간/예측** 방식으로 네트워크 엔진을 새로 설계해야 합니다. 이번 버전은 이 구조를 교체한 것은 아닙니다. 게임 자체가 2D HTML 버전이라는 점도 같습니다.

## 검증 및 주의

- JavaScript 문법, Python 서버 문법, 기존 릴레이 테스트를 실행합니다.
- 현재 사용자 PC와 한국 인터넷에서의 실제 렉 감소량은 직접 측정할 수 없습니다.
- FPS는 표시에 가까운 수치로, 모니터 새로고침 간격이나 브라우저 제한에 영향을 받습니다.
